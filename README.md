## Vilka verktyg vi har använt

- HTML5
  `semantic HTML (header, nav, ul, li, main, h1, h2, h3, p, section, table, footer)`
  För att skapa en tillgänglig tydliga struktur på webplatsen.

  `Använt den endimmesionella Flexbox-modellen för layouten`
  För att sidan ska se fint ut.
- Git
  `Lokal versionshantering via terminalen`
  För att spara olika versioner av projektet under arbetsgång.
  `Github`
  För att lagra projektets källkod i molnet, möjliggör smidigt samarbete i grupper

### Vad är skillnaden mellan Git och Github

1. Vad är skillnaden mellan git add och git commit?
   > Git add används för att staga koden man har skrivit medan git commit är för beskriva vad man har ändrat i sin kod.
2. Varför använder man branches istället för att jobba direkt i main?
   > Man använder branches för olika anledningar. Om det är många som jobbar på samma projekt kan man ta en feature eller issue och jobba på den i en seperat gren. Då påverka man inte main branchen, vilket gör att man inte förstör koden om nogåt blir fel.
3. Vad händer rent praktiskt när man gör en merge?
   > När man gör en merge från en gren(branch) till main, så slås all kod en enhet, om det inte upstår några konflikter.
4. Vad är skillnaden mellan att pusha till GitHub och att publicera direkt på t.ex. Netlify?
   > Att pusha innebär att man skickar sin lokal kod till remote repository till example Github.Netlify är istället en tjänst man använder för att publicera sin hemsida och gör den levande.
5. Om du vill exkludera någon fil i projektet från versionshanteringen, hur gör du då?
   > För att exkludera någon fil till example .env fil, använder man en .gitignore fil. I .gitignore skriver man namnet på filen för att säga till Git att inte spåra eller inkludera själva filen i versionhanteringen.
